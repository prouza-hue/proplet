# Monthly competition quality v2 — data and rollout contract

Prepared 2026-11-01 against production/main `6cfca03` (v4.10.1). This file records implementation and local verification; production activation is a separate action.

The forward migration is `supabase/migrations/20261101013000_monthly_quality_v2.sql`. It changes no game XP, result receipt, patron record, news receipt, enabled flag, launch month, or existing closed-month snapshot. `monthly_competition_settings.scoring_version` defaults to **1**, so migration application alone preserves v1 reads, ingestion and finalization. Complete historical v1 acceptance runs against this dormant full schema.

After the new client/backend is deployed, the service-only RPC `proplet_activate_monthly_quality_v2()` sets version 2 and reconciles every still-open eligible month in one transaction. This recovers genuine November 1 activity from the owned atomic evidence, without replaying game rewards. Retrying activation recomputes deterministically. Do not apply the isolated QA-clock migrations to production; they are part of disposable CI bootstrap only.

Daily quality uses the existing `server.py::_daily_individual_score` definition: completion 55, clean 15, `max(10-3*hints,0)`, speed 0–20. Verified same-day first-completion times use best-position percentile; equal times get the same percentile, and a singleton verified cohort gets 10. Daily total rounds to one decimal. Unverified/unknown time contributes no speed and never enters the verified speed cohort. Calm Daily is excluded. Accepted offline results keep their actual Prague completion day and remain eligible through the existing month-end +48-hour receipt cutoff. There is no new per-day synchronization cutoff.

Only the best 20 Daily days count (maximum 2000). Equal day scores select clean first, fewer hints, verified elapsed ascending with unknown last, then date for stable identical choices. All counters/time facts come from the selected days. Any selected unknown time makes the aggregate `verifiedTimeMs` null, placing it after completely verified elapsed sums at that tie breaker.

Other activity is actual first-completion XP from `free` (including genuine newly rewarded archive play), `daily_special`, and `tajenka`, completed in that Prague month and received before the same monthly review cutoff. It requires owned runs, durable first-completion receipts with positive awarded XP, no transferred historical slot, and the matching current official game result. Current result XP can cap a receipt downward. Repeats/replays, starter/training/practice, basic Daily base XP, account/referral/patron rewards, discoveries and all recovery reward ledgers are excluded. Calm other play may contribute its genuinely earned game XP. `otherPoints = min(500, round(otherEarnedXp/12,1))`; credited XP caps at 6000. Total maximum is 2500 and displayed/ranked precision is one decimal.

Rank order is total descending, Daily subtotal descending, counted clean days descending, counted hints ascending, verified elapsed sum ascending (unknown last). Exact remaining live ties share a rank with `drawPending=true`. Finalization rebuilds all accepted Daily cohorts under the month lock, creates one persistent random seed, derives one stable draw ordering, and stores unique ranks and unique 1/2/3 badges. Refresh/retry cannot redraw. The private draw row records method, seed and creation time. A closed v2 correction requires the existing reason/operator/idempotency/CAS audit boundary, recomputes cohorts, reuses the seed and updates snapshot/badges atomically. Closed v1 rounds keep their original version and shared-rank rules.

API additions: `scoringVersion:2`, `rulesVersion:"monthly-quality-v2"`, `endsAt`, and `scoring` caps. Standings and `me` add `dailyPoints`, `otherPoints`, `otherEarnedXp`, `otherCreditedXp`, `cleanCount`, `hintCount`, `verifiedTimeMs`, `unverifiedDays`, `drawPending`, `tieBreakReason`. Reasons are `points`, `dailyPoints`, `cleanCount`, `hintCount`, `verifiedTime`, `draw`, or `pendingDraw`; non-draw reasons compare the adjacent contender. `me.days` adds `completionPoints`, `cleanPoints`, `hintPoints`, `speedPoints`, `hints`, `verifiedTimeMs`, `provisional`. Existing month/status/endDate/closesAt/revision/privacy/top100-plus-own-rank fields remain. Closed v1 states report version 1 and `monthly-basic-v1`.

Native database acceptance remains in `tools/test_monthly_competition_db.py`; it runs the complete v1 suite then explicitly activates and calls `tools/test_monthly_quality_db.py`. New cases cover trusted session timing, exact cohort math, clean/hints, unknown/offline/calm, best20, maximum2500, actual XP provenance and ownership, precision/caps, late sync, concurrent finalizers, immutable draws, audited corrections, legacy snapshot preservation and SQL ranking beyond top100. HTTP acceptance runs the real adapter and checks decimal facts, unique final ranks and UUID privacy. Evidence is recorded in `release-evidence/monthly-quality-database.json`. Local Windows PostgreSQL lacks pg_cron; the scheduler installation is explicitly omitted while the real finalizer is executed concurrently.
